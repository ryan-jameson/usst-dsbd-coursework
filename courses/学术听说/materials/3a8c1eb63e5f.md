## 分节 1

### 1. **JavaBeans类的成员变量一般称为属性（property）。对每个属性访问权限一般定义为private，而不是public。**
- **B. 正确**
- **分析：** JavaBeans规范要求Bean的成员变量（属性）应该是私有的，并且通过公有的getter和setter方法进行访问。这样做可以确保数据的封装性和安全性。因此，属性的访问权限通常定义为 `private`。
### 2. **MVC结构中，JSP页面使用JavaBean，一般用 `<jsp:useBean id="customer" type="com.demo.Customer" />`**
- **B. 正确**
- **分析：** 在MVC模式中，`<jsp:useBean>` 标签用于声明并实例化JavaBean。`id` 属性表示Bean的名称，`type` 属性指定Bean的类类型。`<jsp:useBean>` 是JSP页面与JavaBean交互的标准方式之一。
### 3. **下面哪个是JSP声明？**
- **A. `<%! int count = 0; %>`**
- **分析：** 在JSP中，`<%! ... %>` 用于声明类级别的成员变量和方法，这就是JSP的声明部分。`<% ... %>` 是JSP的脚本部分，用于嵌入Java代码。`<%= ... %>` 用于输出结果。`<%! int count = 0 %>` 声明了一个变量 `count`。
### 4. **哪些被转换为 _jspService() 方法的一部分？**
- **A. JSP小脚本**
- **B. JSP表达式**
- **C. 模板文本**
- **D. JSP声明**
- **分析：** `_jspService()` 方法是JSP容器生成的一个方法，它包含了JSP页面中的所有逻辑部分。JSP中的小脚本（如 `if` 语句）、表达式、模板文本（HTML部分）和声明都将被转换成该方法的一部分。
### 5. **声明的变量仅仅在页面第一次载入时由容器初始化一次。**
- **A. 正确**
- **分析：** JSP中的声明变量（如 `<%! int x = 0; %>`）在页面第一次加载时由容器初始化一次，并且在随后的请求中不会被重新初始化。
### 6. **MVC模式中，控制器通常不直接向客户输出数据**
- **A. 正确**
- **分析：** 在MVC模式中，控制器（Controller）负责处理请求、协调模型和视图之间的交互，但它通常不直接输出数据。它将模型（Model）的数据传递给视图（View）进行展示。
### 8. **4个作用域对象，作用范围最大的是**
- **A. application**
- **分析：** JSP和Servlet中有四个作用域：`pageContext`（页面级作用域），`request`（请求级作用域），`session`（会话级作用域）和`application`（应用级作用域）。`application` 是作用范围最大的一种，它可以在整个Web应用中共享数据。
### 10. **下列哪些是合法的JSP隐含变量？**
- **A. out**
- **B. request**
- **C. servletContext**
- **分析：** JSP隐含对象是JSP容器自动创建并提供给开发者的对象。常见的隐含变量包括 `out`（输出流），`request`（请求对象），`response`（响应对象），`session`（会话对象），`application`（应用上下文），以及 `servletContext`（Servlet上下文）。`stream` 不是一个合法的JSP隐含变量。
### 11. **image.png访问某JSP页面后，再次访问该页面，则执行上面哪些阶段？**
- **分析：** 在JSP生命周期中，首次请求页面时会经历多个阶段（如初始化、编译等）。但在随后的请求中，只有部分阶段会被执行。根据上下文，选项B最合适，表明某些步骤会在请求时执行，但不会完全重新执行所有步骤。
- **分析：** JSP中，`<%! int x = 10; %>` 是声明阶段，将 `x` 初始化为 10。`<% x = 1; %>` 会修改 `x` 的值为 1。`<%= ++x %>` 输出 `x` 增加后的值，即 11。
### 13. **<jsp:setProperty name="customer" property="\*" /> 代码的含义是：**
- **C. 使用请求参数的每个值为JavaBean属性赋值**
- **分析：** `<jsp:setProperty>` 标签用于将请求中的参数赋值给JavaBean的属性。`property="*"` 表示将所有请求参数的值赋给JavaBean中的对应属性。
### 14. **JSP中有如下代码：<% count++; %> 仅仅在页面第一次载入时由容器执行一次**
- **B. 错误**
- **分析：** 该代码会在每次请求页面时执行，而不是仅在第一次加载时执行。每个请求都会重新执行JSP中的代码。
### 15. **copyright.html是静态页面，JSP执行如下代码： `<%! String pageURL ="copyright.html"; %>  <%@ include file="<%= pageURL %>" %>` 能否将页面copyright.html包含进来？**
- **B. 能**
- **分析：** 这段代码会正常工作。`<%@ include %>` 是静态包含指令，在页面加载时会将指定的文件包含进来，即使 `pageURL` 是一个变量。
### 16. **<jsp:useBean id="customer" class="com.demo.Customer" scope="session" />的含义是：该动作在指定作用域中查找类型为Customer的实例，如果找到用customer指向它，如果找不到产生Instantiation异常。因此，使用type属性必须保证bean实例存在。**
- **A. 错误**
- **分析：** `scope="session"` 会使Bean在会话范围内有效。如果 `customer` 没有找到，容器会根据 `class` 属性创建一个新的 `Customer` 实例。`type` 属性不需要保证实例存在，容器会自动创建。
### 17. **如果设置了 `<%@ page contentType="text/html;charset=UTF-8" %>`，但没有设置pageEncoding，则pageEncoding属性的值为**
- **D. utf-8**
- **分析：** 如果 `contentType` 设置了字符编码 `UTF-8`，那么 `pageEncoding` 会默认设置为 `UTF-8`。
### 18. **<% int m=9; %> <%! int n = 6; %> <%! int m = 8; %> <% int n=3; %> <%= m+n %> 以上JSP执行结果是**
- **B. 12**
- **分析：** 在JSP中，变量声明的顺序很重要。这里 `n` 会被声明两次，但最后的 `n` 是在 `int n = 3` 之后，所以 `m` 取值为 9，`n` 取值为 3，结果是 9 + 3 = 12。
### 19. **【结构1】 <% pageContext.forward("other.jsp"); %> 【结构2】 <jsp:forward page="other.jsp" /> 结构1和结构2的含义是相同的**
- **B. 正确**
- **分析：** 这两种方式都用于转发请求到另一个JSP页面，效果相同，都是将控制权转交给另一个页面。
### 20. **JSP中如下代码 `<%= count; %>` 是否正确？**
- **B. 正确**
- **分析：** `<%= count; %>` 是JSP中的表达式，用于输出变量的值。如果 `count` 是一个有效的变量，它会被输出到响应中。
