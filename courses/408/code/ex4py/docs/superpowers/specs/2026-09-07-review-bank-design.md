# 085411 Python 复习题库扩展设计

## 问题
原题库按知识点递进，适合首次学习，但每个模式出现次数有限。复习阶段需要相同算法在不同表述、数据边界和输出要求中再次出现，从而训练“读题后快速识别算法”与无提示复现。

## 方案比较
- 只随机重做原题：零新增内容，但容易记住答案而非识别算法。
- 再增加互不相关的题：题量上升，但继续制造新知识负担。
- 每个算法原型生成三种变体：既保持熟悉度，又迫使学习者重新读题和处理边界。本项目采用此方案。

## 内容结构
新增 60 道 R 系列题，20 个算法原型各 3 题。每三个变体遵循“直接复现—边界变化—场景包装”：第一题巩固标准模板，第二题加入负数、重复、不可达或边界条件，第三题使用不同业务题面但保持核心算法不变。20 个原型归入 10 个复习组，每组 6 题。

## 数据与兼容性
`problems/review_bank.py` 单独保存复习内容。`trainer/catalog.py` 同时建立核心题库和复习题库索引；`problems_for_day()` 仍只返回 D 系列。已有 `get_problem()` 扩展为支持 R 系列，因此 start/test/submit/hint/solution 无需两套判题路径。进度继续使用题号作为键，不迁移既有记录。

## CLI
新增嵌套命令：
- `review list [group]`：列出全部复习组或指定组题目与完成状态。
- `review next [group]`：推荐指定范围内第一道未通过题。
- `review mix [count]`：从不同复习组轮转选取未通过题，创建答题文件并输出清单。

`status` 分别显示核心 60 题与复习 60 题进度；`doctor` 检查核心 60、复习 60、总计 120。

## 安全与错误处理
所有 R 题复用现有非覆盖式 workspace 创建、子进程超时判题和原子进度写入。无效分组、题号或数量返回用户错误码 2。混合训练只创建不存在的答题文件，不覆盖任何已有解答。

## 测试
测试先固定旧题库快照，再验证复习数量、ID 格式、分组分布、字段完整性、CLI 推荐、混合训练和状态输出。最后逐题运行 120 份参考答案的公开与隐藏用例，并重新运行完整回归套件和编译检查。
