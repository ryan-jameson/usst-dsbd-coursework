# 校园跑步路径规划问题与解法 v1

## 1. 问题背景

跑步打卡系统会为学生随机生成 5 个打卡点。学生可以按照任意顺序跑至这些指定位置，并通过卫星定位完成打卡。系统要求相邻两次打卡之间的时间间隔不超过 5 分钟，因此路线规划是否合理，会直接影响学生是否能够按时完成打卡任务。

本实验依据附件中的上海理工大学校园道路图和打卡点坐标数据，尝试建立一个从地图识别、路网构建、路径规划到随机打卡点生成的完整建模流程。

## 2. 已有数据

当前使用的数据包括：

1. 校园道路图：
   - 文件：`E3 - 校园跑步路径的规划/附件：上海理理工大学跑步打卡/附件1：上海理工大学校园道路图.jpg`
   - 图片大小：`5000 × 5000`
   - 坐标原点按题目要求取左上角标记点方向，即图像左上为坐标原点，横轴向右，纵轴向下。

   - 每名同学有 1 个文字起点和 5 个打卡点坐标。

因此，现有 v1 模型主要优化 5 个打卡点之间的访问顺序，没有把文字起点精确纳入路线规划。

## 4. v1 解法总体思路

当前 v1 解法可以概括为：

> 校园地图图片 → 道路区域识别 → 道路骨架化 → 加权无向图构建 → 打卡点投影 → 最短路计算 → 访问顺序枚举 → 路线可视化 → 随机打卡点生成与检验

核心思想是把校园道路从图片中转化为图结构，然后把跑步路线规划问题转化为图上的最短路和小规模旅行商问题。

## 5. 地图道路识别方法

### 5.1 图像预处理

原图较大，直接处理成本较高。因此 v1 中先将图片按比例缩小：

```python
scale = 0.20
```

也就是把 `5000 × 5000` 的原图缩小为约 `1000 × 1000` 的图像。

### 5.2 HSV 颜色空间识别

地图中不同区域颜色比较明显：

- 绿色：绿化休闲
- 粉色：生活服务
- 蓝色：教学科研
- 灰色：体育场馆
- 白色：道路、停车场

因此 v1 使用 HSV 颜色空间进行识别：

- 高饱和度区域用于定位校园主体范围；
- 低饱和度、高亮度区域用于提取道路候选区域。

### 5.3 校园主体区域提取

先用高饱和度区域找出校园主体：

```python
colored_mask = (saturation > 0.25) & (value > 0.25)
```

然后使用形态学操作扩大、闭合并填充校园区域：

```python
binary_dilation
binary_closing
binary_fill_holes
```

这样做的目的是避免把地图外部大片白色背景误判为道路。

### 5.4 道路区域提取

道路区域按如下阈值提取：

```python
road_mask = (saturation < 0.18) & (value > 0.78) & campus_mask
```

即：

- 饱和度较低；
- 亮度较高；
- 位于校园主体区域内部。

### 5.5 道路骨架化

道路区域通常有宽度，不适合直接作为图节点。v1 使用骨架化方法将道路区域压缩为单像素宽度的中心线：

```python
skeletonize(road_mask)
```

骨架化后的道路中心线用于后续构造路网图。

## 6. 加权无向图构建

v1 将道路骨架中的每一个像素点视作一个图节点。

如果两个骨架像素在 8 邻域中相邻，则在它们之间建立一条无向边。

边权定义为原图像素尺度下的欧氏距离：

```python
weight = hypot(dx, dy) / scale
```

其中：

- 水平或竖直相邻边的权重约为 `1 / scale`；
- 对角相邻边的权重约为 `sqrt(2) / scale`；
- 在当前 `scale = 0.20` 下，水平或竖直边权约为 5 个原图像素。

当前路网图规模约为：

- 道路骨架节点数：约 12119
- 道路骨架边数：约 12677

输出图：

`math_modeling_experiments/outputs/e3_road_extraction.png`

该图包含：

1. 原始校园地图缩略图；
2. 识别出的道路区域；
3. 加权无向路网图表示。

## 7. 打卡点投影

附件中的打卡点坐标是原图像素坐标。

由于提取出的道路图是离散骨架节点，打卡点不一定刚好落在道路骨架上，因此 v1 使用最近邻方法将打卡点投影到最近的路网节点。

实现方式：

```python
cKDTree(graph_positions)
```

对于每个打卡点 `(x, y)`，查找距离它最近的道路骨架节点，作为该打卡点在路网图上的代表位置。

模型中记录了平均投影误差，用于粗略衡量坐标点与道路网络的匹配程度。

## 8. 路线规划算法

### 8.1 两点间最短路

任意两个打卡点之间的路径长度，通过加权无向图上的最短路计算得到：

```python
nx.shortest_path(G, u, v, weight='weight')
```

最短路长度为：

```python
nx.path_weight(G, path, weight='weight')
```

### 8.2 五个打卡点访问顺序优化

每名同学有 5 个打卡点。由于顺序任意，因此需要确定访问顺序。

v1 采用全排列枚举法：

```python
permutations(range(5))
```

共 `5! = 120` 种路线顺序。

目标函数为总路程最短：

```text
min sum d(P_i, P_j)
```

即在每一种访问顺序下，计算相邻打卡点之间的最短路距离之和，选择总距离最小的顺序。

### 8.3 输出结果

对每名同学输出：

- 学生编号；
- 文字起点；
- 最优访问顺序；
- 总路程，单位为像素；
- 估计总路程，单位为米；
- 最大相邻路程；
- 最大相邻时间；
- 是否满足 5 分钟间隔；
- 平均投影误差。

其中像素到米的换算目前是假设参数：

```python
ASSUMED_M_PER_PIXEL = 0.45
RUNNING_SPEED_M_PER_MIN = 160.0
```

也就是假设：

- 1 像素约为 0.45 米；
- 跑步速度约为 160 米/分钟。

## 9. 优化过程展示

最初版本中，优化过程图是一条水平线。原因是当时先把所有访问顺序按总路程从小到大排序，再计算 `cummin()`，导致第一项就是全局最优。

现在已经调整为：

1. 保留全排列的原始枚举顺序；
2. 每评价一种访问顺序，就记录当前总路程；
3. 使用 `cummin()` 计算搜索过程中“当前已发现的最优路线”；
4. 左图展示当前最优总路程随评价次数的变化；
5. 右图单独展示前 10 个较优访问顺序。

输出图：

`math_modeling_experiments/outputs/e3_route_optimization_process.png`

不过，由于全排列枚举只有 120 种，而且较优方案可能很早被发现，因此这张图的下降过程仍然比较短。

## 11. 低聚集打卡点生成算法

题目要求设计新的打卡点生成算法，使同时发生的跑步路线尽可能减少聚集。

v1 的做法是先把像素级路网进一步简化为“道路段图”。

### 11.1 道路段图构建

在道路骨架图中：

- 度数不等于 2 的节点视为路口或端点；
- 两个路口之间连续的一段骨架视为一条道路段。

这样可以把大量像素节点压缩成更符合直觉的道路结构。

当前简化后得到：

- 路口/端点数量：约 1350
- 道路段数量：约 1906

### 11.2 “不超过 3 条道路”的定义

在简化道路段图上，相邻打卡点之间最短路径经过的边数，视作经过的道路条数。

因此约束：

```text
每两个打卡点间的距离不超过 3 条道路
```

在 v1 中被解释为：

```text
规划顺序中相邻两个打卡点在道路段图上的最短路径边数不超过 3
```

### 11.3 低聚集生成策略

v1 使用贪心随机搜索：

1. 从候选路口中随机选择第一个点；
2. 后续点从当前点 3 条道路范围内的候选点中选择；
3. 对若干候选组计算可行路线；
4. 用共享道路段数量作为拥挤惩罚；
5. 优先选择与已有路线共享道路段少的方案。

目标函数大致为：

```text
目标函数 = 总路径长度 + 拥挤权重 × 共享道路段数
```

当前使用：

```python
congestion_weight = 2000.0
```

当前方案的优点是：

1. 流程完整：

2. 可运行：

## 14. v1 方案的主要局限

当前方案也有明显不足，这也是后续需要重构算法设计的原因。

### 14.1 道路识别过于依赖颜色阈值

当前道路识别主要依赖 HSV 阈值：

```python
saturation < 0.18
value > 0.78
```

这会带来几个问题：

- 白色建筑空地可能被误识别为道路；
- 道路边界可能过宽；
- 细路、彩色道路、灰色道路可能漏检；
- 阈值对地图风格敏感。

### 14.2 路网节点过细

当前像素级路网把每个骨架像素都当成节点，节点数超过一万。

这虽然精细，但也带来问题：

- 图规模偏大；
- 路径呈现可能锯齿化；
- 不符合真实“道路-路口”的抽象；
- 后续优化算法复杂度较高。

### 14.3 起点没有真正纳入模型

附件中“起点”是地点名称，如第五食堂、图书馆等，但没有给出像素坐标。

当前 v1 只优化 5 个打卡点之间的访问顺序，没有把起点到第一个打卡点的距离纳入目标函数。

这会降低模型的真实性。

### 14.4 访问顺序算法太简单

当前只有 5 个点，因此直接枚举 120 种顺序即可得到最优。

这导致：

- 算法挑战度不高；
- 优化过程展示不够丰富；
- 不适合扩展到更多打卡点；
- 不能体现复杂优化算法的价值。

### 14.5 拥挤度模型比较粗糙

当前拥挤度只用共享道路段数量表示。

它没有考虑：

- 不同学生出发时间；
- 跑步速度差异；
- 路段宽度；
- 路段容量；
- 同一时间段内的动态相遇概率；
- GPS 打卡误差半径。

### 14.6 5 分钟约束缺少真实比例尺

当前像素距离到实际距离的换算是假设值：

```python
ASSUMED_M_PER_PIXEL = 0.45
```

如果没有真实地图比例尺，时间约束只能做相对检验，不能严格证明实际可行。

## 15. 下一版重构方向

如果要让算法更有研究性和挑战性，建议 v2 从以下方向重构。

### 15.1 从“像素路网”升级为“拓扑路网”

不要直接用一万多个骨架像素做核心路网，而是把路网压缩成：

- 路口节点；
- 道路段边；
- 道路段长度；
- 道路段类型；
- 道路段拥挤度；
- 道路段容量。

这样更符合真实道路网络。

### 15.2 引入多目标优化

不只最小化总路程，可以同时考虑：

```text
目标 = 路径长度 + 超时惩罚 + 拥挤惩罚 + 绕行惩罚 + 打卡点分散度惩罚
```

可建立多目标规划模型。

### 15.3 使用启发式算法替代简单枚举

虽然 5 个点可以枚举，但为了体现研究性，可以设计更通用的算法：

- 遗传算法；
- 模拟退火；
- 蚁群算法；
- 禁忌搜索；
- A* + TSP 混合算法；
- 多智能体路径规划。

其中比较适合本题的是：

```text
A* 最短路 + 遗传算法优化访问顺序 + 拥挤度动态惩罚
```

### 15.4 设计动态拥挤度模型

可以把每名学生路线看作随时间推进的路段序列。

若两个学生在相近时间经过同一条路段，则增加拥挤惩罚。

拥挤度可以定义为：

```text
C_e(t) = 同一时间窗口内经过路段 e 的人数
```

总拥挤代价：

```text
sum C_e(t)^2
```

平方惩罚能更强烈地避免集中。

### 15.5 打卡点生成改成约束优化问题

当前打卡点生成是随机贪心。

v2 可以改成：

- 先生成候选点池；
- 根据路网距离构造可达图；
- 在候选点池中选择 5 个点；
- 要求任意相邻点在某个访问顺序下满足 3 条道路约束；
- 最大化不同学生路线之间的距离或最小化重叠。

可以写成：

```text
maximize 路线分散度
subject to 每组 5 点可行
           相邻点不超过 3 条道路
           点位不重复或低重复
```

### 15.6 加入起点坐标标注

可以人工在地图上标注文字起点对应的像素坐标，例如：

- 第五食堂；
- 图书馆；
- 教学大楼 C 座；
- 校长办公室；
- 毛主席像。

标注后，路线规划变成：

```text
固定起点 + 5 个打卡点任意顺序
```

这比当前模型更符合题意。

## 16. v1 到 v2 的推荐升级路线

建议下一版按这个路线重构：

1. 保留当前地图识别结果，但把核心路网从像素图换成道路段拓扑图；
2. 人工或半自动标注文字起点坐标；
3. 将每名同学的路线规划改成“固定起点 + 5 打卡点 TSP”；
4. 把路线目标从单一最短路升级成多目标函数；
5. 引入遗传算法或模拟退火展示更明显的优化过程；
6. 将多人路线规划改成带拥挤惩罚的联合优化；
7. 重新设计随机打卡点生成算法，使其本身成为一个约束优化问题；
8. 输出更有说服力的结果检验表，包括路线长度、最大相邻时间、道路段数、共享路段数、拥挤度指标。

## 17. 当前 v1 版本一句话总结

当前 v1 版本完成了从地图图片到路径规划的基本建模闭环，但核心算法仍偏简单：道路识别依赖阈值，路径规划依赖小规模全排列，拥挤控制依赖贪心随机搜索。它适合作为基线版本，但如果要做出更有研究性和挑战性的课程报告，下一步应重构为“道路段拓扑图 + 多目标优化 + 多人动态拥挤控制”的算法框架。
