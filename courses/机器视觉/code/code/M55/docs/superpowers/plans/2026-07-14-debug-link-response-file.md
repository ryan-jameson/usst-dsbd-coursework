# Debug Link Response File Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent the Debug linker command from exceeding the Windows command-line limit by passing generated object and library inputs through a GNU response file.

**Architecture:** Keep the Eclipse-generated source/object discovery unchanged. The `rtthread.elf` Make rule writes `$(OBJS) $(USER_OBJS) $(LIBS)` to `link_objects.rsp`, then invokes `arm-none-eabi-gcc` with `@link_objects.rsp`; GNU ARM GCC expands that file after process creation.

**Tech Stack:** GNU Make 4.x, GNU Arm Embedded GCC, RT-Thread Studio Eclipse managed build.

- [x] **Step 2: Add a response-file prerequisite and short linker command**

```make

	$(file >$@,$(OBJS) $(USER_OBJS) $(LIBS))

	arm-none-eabi-gcc -mcpu=cortex-m7 -mthumb -mfloat-abi=hard -mfpu=fpv5-d16 -O3 -ffunction-sections -fdata-sections -Wall -g -gdwarf-2 -T "D:\RT-ThreadStudio\workspace\M55\board\linker_scripts\link.ld" -nostartfiles -Xlinker --gc-sections -Wl,-Map,"rtthread.map" -Xlinker --cref -o "rtthread.elf" @link_objects.rsp
```
