# 分布式系统实验报告

## 1. 实验概述
- **实验目标**：
  - 实验四（RMI）：掌握 Java RMI 远程调用机制，构建学生信息管理的 C/S 应用，完成增删改查的远程方法调用。
  - 实验五（HTTP 客户端）：使用原生 Socket 手写 HTTP/1.0 报文，理解 GET/POST 的请求与响应格式，完成简单“浏览器”功能。
  - 实验六（Web 服务器）：实现基础 Web 服务器，支持静态文件分发与 CGI 调用，理解服务端对 HTTP 报文的解析与响应生成。
- **开发环境**：Windows 平台，JDK 8+/11+（标准类库即可），编辑器/IDE 可为 VS Code 或 IntelliJ IDEA，终端使用 PowerShell。

## 2. 实验四：RMI 学生信息管理系统
### 设计思路
- 分层结构：
  1. **Model**：`Student` 可序列化实体，封装学号与三科成绩。
  2. **Remote Interface**：`IRemoteStudentService` 继承 `Remote`，声明增删改查与 `getAllStudents`。
  3. **Server Impl**：`RemoteStudentServiceImpl` 继承 `UnicastRemoteObject`，用 `HashMap<String, Student>` 作为内存库，记录日志。
  4. **Server Main**：`RMIServer` 创建 registry(1099) 并 `bind("StudentService", service)`。
  5. **Client Main**：`RMIClient` `lookup` 远程对象，顺序测试增删改查。

## 3. 实验五：HTTP 客户端浏览器
### 设计思路
- 基于 Socket，手动拼接 HTTP/1.0 请求行与头部，遵循 CRLF (`\r\n`) 作为行结束，空行分隔头和体。
- GET：`GET /path HTTP/1.0` + `Host` 头；无请求体。
- POST：`POST /path HTTP/1.0` + `Host` + `Content-Type: application/x-www-form-urlencoded` + `Content-Length`，随后发送请求体。
- 响应解析：读取状态行、响应头；根据 `Content-Length` 读取正文，否则读到 EOF。

### 核心代码分析
- 报文构建：严格使用 `\r\n`，末尾空行表示头结束；`Content-Length` 按 UTF-8 字节长度计算。[此处插入代码]
- 解析逻辑：先读状态行提取状态码，再按行解析头部 Map，依据 `Content-Length` 精确读取 body。[此处插入代码]

### 运行结果

- POST 测试：向 `/cgi-bin/test.bat` 提交 `name=Alice&score=90`，控制台打印 CGI 输出 HTML。

## 4. 实验六：Web 服务器程序
### 设计思路
- 主线程：`ServerSocket(8080)` + `while(true) accept`。
- 并发：为每个连接创建新线程 `ClientHandler`，简单支持多请求并发。
- 路由：
  - `/cgi-bin/` 前缀走 CGI 执行。
  - 其他路径走静态文件：根目录 `webroot`，`/` 映射 `index.html`。
- 安全：禁止路径含 `..`，防目录穿越。

- 架构/时序示意：
```mermaid
sequenceDiagram
    autonumber
    participant Browser
    participant WebServer
    participant FileSys as Webroot/CGI
    Browser->>WebServer: TCP 连接 + HTTP 请求
    WebServer->>WebServer: 解析请求行/头
    alt 路径以 /cgi-bin/
        WebServer->>FileSys: exec CGI 脚本
        FileSys-->>WebServer: CGI 输出
    else 静态文件
        WebServer->>FileSys: 读取文件
        FileSys-->>WebServer: 文件字节
    end

```

### 运行结果

## 5. 实验总结与心得
- **RMI vs Socket**：RMI 封装了序列化、网络传输与远程调用语义，开发者以接口方式调用；Socket 需手动处理协议细节、报文格式与字节流，但灵活性更高。
- **协议理解**：HTTP 是文本协议，严格的行结束与头体分隔是互操作的基础；RMI 则通过 Stub/Skeleton 隐藏底层通信，强调接口契约与序列化兼容。
- **收获与改进**：
  - 理解了从高层远程调用（RMI）到底层字节流（Socket/HTTP）的完整链路。
  - 认识到路径安全、端口占用、编码与长度计算等细节的重要性。
  - 可改进方向：实现 HTTP/1.1 持久连接与分块传输；为 CGI 增加请求体解析；为 RMI 服务增加持久化或并发控制；为客户端/服务器补充单元测试与更完备的异常处理。
