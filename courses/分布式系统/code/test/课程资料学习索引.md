#### 核心结论

- 多处理机共享主存；多计算机没有共享主存，只能通过消息传递通信（第 28-30、50 页）。
- 设计目标不能只看性能，还要同时考虑透明性、开放性、可靠性、可伸缩性及复杂度。

### 第二章 分布式系统的通信（65 页）

#### 页面范围

| 页码 | 内容 |
|---:|---|
| 2-6 | OSI 分层协议、典型消息结构、ATM |
| 7-25 | 客户—服务器通信；寻址；阻塞/非阻塞；有缓冲/无缓冲；可靠/不可靠原语 |
| 26-45 | RPC：存根、参数传递、动态绑定、故障语义、确认、关键路径、拷贝、计时管理 |
| 46-55 | 组通信：开放/封闭组、对等/分层组、成员、编址、消息顺序、重叠与可伸缩性 |
| 56-65 | 小结与练习 |

#### 核心结论

- RPC 的目标是让远程调用在编程接口上尽量像本地调用，但网络、异构表示和故障使两者语义不可能完全相同。
- RPC 的完整调用链在第 28 页：客户过程 -> 客户存根 -> 本地内核 -> 远程内核 -> 服务器存根 -> 服务器过程，结果按相反方向返回。
- 失败语义必须区分：找不到服务器、请求丢失、应答丢失、服务器崩溃、客户崩溃和孤儿计算（第 32-37 页）。
- “至少一次”适合幂等操作；“至多一次”可避免重复副作用，但可能不执行。必须结合操作语义判断。
- 阻塞/非阻塞、有缓冲/无缓冲、可靠/不可靠是相互独立的设计维度，不应混为一谈。

#### 教材对应

- 教材第 4 章，PDF 第 99-146 页。
- RPC 重点位于教材 PDF 第 107-119 页；面向消息通信从第 119 页附近开始。

### 第三章 名字服务（67 页）

#### 页面范围

| 页码 | 内容 |
|---:|---|
| 3-13 | 名字、地址、标识符、URL、属性、纯名称及其区别 |
| 15-27 | 名字服务、名字空间、挂载、名字服务器、集中/分布/多副本管理、迭代/递归解析 |
| 28-54 | DNS 名字空间、域与区、资源记录、服务器层次、递归/迭代查询、高速缓存 |
| 56-67 | X.500、DIT/DIB、DSA/DUA、DAP/DSP、LDAP、活动目录域服务 |

#### 核心结论

- 名字用于指向实体；地址指向访问点；标识符应满足唯一、每个实体至多一个、永久不复用等约束。三者不能互换。
- 名字解析是在名字空间中把名字解析为实体属性/地址；位置无关性和位置独立性是不同强度的要求。
- 递归解析由服务器继续向下查询，客户端交互少且便于缓存；迭代解析返回下一服务器地址，客户端承担后续查询。
- DNS 是分层、分区、分布式、带缓存的名字服务。课件第 53 页给出 `y.abc.com` 的 8 个 UDP 报文解析过程。
- 目录服务支持按属性查询，不仅是“名字到地址”的白页服务；X.500/LDAP 是本章的重要代表。

#### 教材对应

- 教材第 5 章，PDF 第 147-184 页。
- 递归/迭代名称解析主要位于教材 PDF 第 167-169 页；DNS 位于约第 170-176 页；LDAP/目录服务位于约第 176-181 页。

### 第四章 分布式系统的同步（86 页）

#### 页面范围

| 页码 | 内容 |
|---:|---|
| 2-18 | 时间、逻辑时钟、物理时钟、时钟漂移、Cristian/Berkeley/平均值算法及应用 |
| 19-25 | 分布式互斥：集中式、Ricart–Agrawala、令牌环及比较 |
| 26-28 | Bully 与环选举算法 |
| 29-52 | 原子事务、ACID、私有工作空间、写前日志、两阶段提交、锁/乐观控制/时间戳 |
| 53-64 | 分布式死锁：忽略、检测、恢复、预防；集中/分布检测；wait-die、wound-wait |
| 65-86 | 小结与练习 |

#### 核心结论与公式

- Lamport 时钟保证：若 `a -> b`，则 `C(a) < C(b)`；逆命题一般不成立（第 7-10 页）。
- 时钟漂移界：`1-p < dC/dt < 1+p`；若两时钟差不超过 `δ`，至少每 `δ/(2p)` 秒重新同步（第 12 页）。
- Cristian 算法依赖时间服务器并估计往返时延；Berkeley 算法由时间守护进程收集时钟、计算平均偏差并通知各节点调整（第 13-16 页）。
- Ricart–Agrawala 每次进入临界区需要 `2(n-1)` 条消息，依赖全序时间戳和所有节点应答（第 20-23 页）。
- 集中式互斥简单但协调者是瓶颈/单点；令牌环消息开销低，但要处理令牌丢失和节点崩溃（第 19、24-25 页）。
- 原子事务的 ACID 为原子性、一致性、隔离性、持久性（第 33-35 页）。
- 两阶段提交解决分布式提交一致性，但协调者或参与者故障可能导致阻塞（第 41 页）。
- wait-die 与 wound-wait 都用事务时间戳预防死锁，但“谁等待、谁回滚”的方向相反（第 63-64 页）。

#### 教材对应

- 时钟、全局状态、互斥、选举：教材第 6 章，PDF 第 185-215 页。
- Lamport/物理时钟约位于教材 PDF 第 187-198 页；互斥约第 200-204 页；选举约第 208-214 页。
- 课件中的事务、两阶段提交、并发控制和分布式死锁超出了教材第 6 章的主线；两阶段提交及恢复可补看教材第 8 章约 PDF 第 275-290 页。

#### 核心结论

#### 核心结论与公式

- 位置透明性：名字不暴露文件当前存储位置；位置独立性更强，文件迁移后名字仍无需改变（第 14-15 页）。
- UNIX 语义要求读到最近写入值；缓存使其代价很高，因而会话语义、不可变文件等模型以较弱语义换取性能（第 17-22 页）。
- 无状态服务器易恢复和扩展，但请求必须自包含；有状态服务器容易支持会话和优化，但故障恢复更复杂（第 29-30 页）。
- 复制表决要求读法定数 `Nr`、写法定数 `Nw` 满足 `Nr + Nw > N`，保证读集合与最近写集合相交；通常还要求 `Nw > N/2`，防止两个写集合互不相交（第 47-49 页）。
- 课件示例：`N=12, Nr=3, Nw=10`；另给出 `Nr=7, Nw=6` 与 `Nr=1, Nw=12`（第 48-49 页）。

- 教材第 11 章，PDF 第 372-412 页，重点以 NFS、Coda 等系统说明文件服务、命名、缓存、复制、容错和安全。

### 第七章 分布式共享存储器（100 页）

#### 页面范围

| 页码 | 内容 |
|---:|---|
| 2-11 | 多处理机/多计算机与 DSM 的基本思想、优缺点 |
| 12-43 | 芯片/总线/环/交换式共享存储器；缓存一致性；SMP、NUMA、MPP |
| 44-58 | 基于分页的 DSM：复制、粒度、顺序一致性、置无效、拥有者/副本定位、页面置换、同步 |
| 59-85 | 数据中心一致性：严格、顺序、因果、PRAM、处理器、弱、释放、入口一致性 |

#### 核心结论

- DSM 用软件/MMU 在多计算机上模拟共享虚拟地址空间，简化编程，但会产生页迁移、错误共享和一致性开销（第 10-11、44-58 页）。
- 一致性强弱不是“正确/错误”的二分，而是应用可观察到的读写顺序约束；约束越强，通常通信与同步成本越高。
- 无显式同步的一致性由强到弱：严格 -> 顺序 -> 因果 -> 处理器 -> PRAM（第 84 页）。
- 使用同步操作的模型：弱一致性在同步完成后保证共享数据一致；释放一致性在离开临界区时传播更新；入口一致性在进入临界区时更新与该临界区相关的数据（第 80-85 页）。
- 最终一致性只保证在长期无更新时副本最终收敛；它不保证单个客户跨副本访问时的体验，因此需要单调读、单调写、写后读、读后写等客户中心保证（第 86-98 页）。

## 5. 高频易混概念

| 概念对 | 区别 |
|---|---|
| 多处理机 vs 多计算机 | 前者共享主存；后者无共享主存，通过消息传递通信 |
| 名字 vs 地址 vs 标识符 | 名字指向实体；地址指向访问点；标识符用于稳定、唯一地区分实体 |
| 位置透明性 vs 位置独立性 | 前者隐藏当前位置；后者允许迁移后仍保持名字不变 |
| 阻塞 vs 非阻塞 | 是否等待操作完成/取得控制权；不等同于可靠性 |
| 有缓冲 vs 无缓冲 | 是否通过邮箱/队列暂存；不等同于同步/异步 |
| 至少一次 vs 至多一次 | 前者可能重复执行；后者保证不重复但可能零次 |
| 递归解析 vs 迭代解析 | 前者由服务器继续查询；后者把下一服务器地址返回给请求方 |
| 逻辑时钟 vs 物理时钟 | 前者保证事件顺序关系；后者逼近真实时间 |
| 顺序一致性 vs 因果一致性 | 前者所有进程看到同一全局顺序；后者只强制因果相关写操作同序 |
| PRAM vs 处理器一致性 | 处理器一致性 = PRAM 的单处理器写顺序保证 + 对同一存储位置的相关性约束 |
| 位置透明/独立 vs 缓存一致性 | 前者是命名属性；后者是多副本/缓存读写可见性属性 |
| 硬实时 vs 软实时 | 硬实时错过截止时间即系统失败；软实时允许有限的性能降级 |
