1.1 大数据定义、特征与应用
来源：PPT 12-18

• 大数据不是单指“数据很多”，而是规模、增长速度和多样性超出常规软件可承受范围，需要新的处理模
式来提升决策、洞察和流程优化能力。
• 5V+1C：Volume 容量大；Variety 来源、类型和表示多样；Value 价值大但价值密度低；Velocity
产生和处理速度快、时效性强；Veracity 强调准确与可信；Complexity 强调处理分析复杂。
• 典型应用：科研、交通、通信、医疗、金融、制造、体育、个性化生活和安全。
• 我国发展阶段（按
PPT）：预热、起步、落地、深化、高速发展；主要困难是原创技术不足和数据开放共享水平较低。

• 一般处理链：数据源 -> 采集 -> 预处理 -> 存储与管理 -> 分析/挖掘 -> 可视化与应用。

2.1 传统数据采集
来源：PPT 3-17

• 传统采集把传感器获得的非数字信息，经信号调整、采样、量化、编码和传输，转换为数字信号并存入计
算机；软硬件集合称为数据采集系统。
• 按是否存在信息反馈分为开环与闭环；评价指标主要是精度和处理速度。
• 系统形态：微型计算机系统适合中小规模、成本低；集散型系统适应性强、可靠、实时；软件包括模拟/数
字/脉冲/开关信号处理、参数设置、主控和通信。
关键技术

定义

考试抓手

采样

把时间和幅值连续的模拟信号变为时间离散的脉
冲信号

采样频率 fs >= 2 fmax 才能无失真恢复

量化

用最接近的最小数量单位整数倍代替采样幅值

幅值由连续变离散

编码

用二进制代码表示量化值

A/D 转换器完成量化与编码

采样方式

常规、间歇、变频

常规存储最大；间歇以丢信息换空间；变频随信号变化

2.3 HDFS
来源：PPT 32-43

• 数据管理演进：文件系统 -> 数据库系统 -> 数据仓库 ->
分布式系统。分布式系统强调节点自治的内聚性和对用户透明。
• HDFS 目标：存储超大文件、流式批量访问、运行于普通商用硬件；主从结构包含
NameNode、DataNode、Block、Secondary NameNode。
• 优点：高容错、适合大数据、流式访问、文件模型简单、高效、跨平台。局限：低延时访问受限、不适合
大量小文件、不支持并发随机写、不支持随机修改。
• 读流程：客户端向 NameNode 请求文件 -> NameNode 返回数据块位置 -> 客户端按块直接从就近
DataNode 读取；NameNode 不传输实际数据。
• 写流程：客户端请求创建 -> NameNode 校验并返回 DataNode 管线 -> 客户端把数据包写入第一个
DataNode，沿 pipeline 复制 -> 各节点逐级确认。

2.4 HBase
来源：PPT 44-63

• HBase 是分布式、面向列、适合非结构化数据的开源数据库；特点是容量巨大、列存储、稀疏、横向热扩
展、高可靠。
• 数据模型索引由行键、列族:列限定符和时间戳组成；Cell 可保存多个版本，数据统一视为字节/字符串。
• 主从架构：HMaster 管理和分配 Region；HRegionServer 处理 Region 的读写并切分大
Region；ZooKeeper 负责选主、状态监控和寻址；数据最终存于 HDFS。
• Region 是分配管理单位；Store 对应一个列族，含 MemStore 和 StoreFile；HLog/WAL
先记录操作以支持恢复。

5.2 robots.txt
来源：PPT 21-28

• robots 是网站与爬虫的访问约定。爬虫先查看站点根目录的
robots.txt；不存在时通常视为可访问所有未受密码保护页面。它是约定，不是隐私保护机制。
• 记录一般以 User-agent 开头，后接 Disallow/Allow；# 表示注释。User-agent: * 对所有机器人生效。
• Disallow 描述不希望访问的 URL 前缀；Allow 描述允许访问的例外；* 匹配任意字符，$ 匹配行尾。
• 避免爬后台、脚本、模板、导航/背景图片等低价值目录；可在 robots.txt 中声明 sitemap。
