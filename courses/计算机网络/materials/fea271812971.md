实验总结：
通过对比集线器与交换机在数据转发机制、冲突域和广播域管理上的差异，本实验揭示了两者在网络架构中的核心作用与局限性：​​
​​集线器采用广播模式转发所有数据包（包括单播、广播和组播）。由于其物理层工作特性，所有端口共享同一冲突域和广播域，导致潜在的冲突频发及带宽竞争。
​​交换机基于MAC地址表实现单播转发，仅将数据包发送至目标主机所在端口。每个端口构成独立冲突域，有效隔离冲突；但默认情况下所有端口仍属同一广播域，广播流量仍会被全体接收。
​​冲突域在集线器环境下，多站点同时发送数据必然引发冲突；交换机通过端口隔离冲突域，允许多站点并发通信。
​​而两者默认均不隔离广播域，广播包会被扩散至所有端口。​
​
实验问题回答：
（1） 集线器在接收到发送给某节点的单播包时是如何转发数据的？交换机又是如何处理单播包的？
集线器接收到单播包后，无条件广播至所有端口（包括源端口）。
交换机通过MAC地址学习建立端口与MAC地址的映射表，单播包仅从目标MAC对应的端口转发。若目标未知，则泛洪至所有端口（除源端口）。

（2） 在以集线器/交换机为中心的以太网中，当多个站点同时发送数据时，是否会发生冲突？为什么？
集线器网络在多站点同时发送数据时必然冲突。因共享介质且工作于半双工模式，信号碰撞无法避免。
交换机网络在默认情况下，单播通信无冲突。交换机为每个端口提供专用通道，冲突域被彻底隔离。但广播或组播仍可能导致多端口响应。

（3） 使用集线器扩大以太网规模时，有没有可能会使以太网的性能下降？为什么？
有可能，集线器将所有端口置于同一冲突域，站点增多时冲突概率呈指数增长（n个站点冲突概率为 1−(1−1/n) n−1）；且总带宽固定时，多站点共享导致实际吞吐量下降。

（4） 使用交换机扩大以太网规模时，有没有可能会使以太网的性能下降？为什么？
一般情况下不会，交换机通过隔离冲突域和全双工模式显著提升容量。但若存在广播风暴或者MAC表溢出情况可能受限，交换机可能退化为泛洪模式。

实验总结：
通过构建多子网环境，本实验深入分析了IP协议的核心工作机制及网络层中路由表与静态路由配置、IP数据包转发过程与IP分片机制。​​
路由器通过静态路由表实现跨子网通信。实验中，Router0、Router1、Router2的路由表均配置了明确的子网路由条目，并通过默认网关指向出口设备。
​​而数据包在传输过程中，源IP和目的IP地址始终保持不变，体现IP协议的逻辑寻址功能。每经过一个路由器，数据帧的源MAC和目的MAC地址会被替换为当前路由器的出接口MAC和下一跳设备的MAC地址，体现链路层的逐跳传输特性。且每经过一个路由器，IP头部TTL字段减1，头部校验和重新计算，确保数据包有效性。
而当数据包大小超过链路MTU时，路由器会对数据包进行分片。实验中，发送1500字节的ICMP包（含20字节IP头和8字节ICMP头）时，总长度为1528字节，需分片为两段：
​​第一片：1480字节数据 + 20字节IP头（总1500字节）。
​​第二片：48字节数据（28原始数据 + 20新IP头）。
分片后的数据包通过相同标识符和偏移量在目的端重组。而当目标网络不存在或路由缺失时，路由器返回ICMP Destination Unreachable报文。

实验问题回答：
（1） 一个 IP 分组经路由器转发后，有哪些字段会发生变化？
​​TTL每经过一个路由器减1，防止环路。
​​头部校验和因TTL变化需重新计算。
​​源/目的MAC地址链路层重新封装，替换为下一跳设备的MAC地址。
​​片偏移与标志位变化当且仅当分片时需更新分片位置和末片标识。

（2） 任务二的步骤 2 中，为什么数据单元的源 MAC 地址和目的 MAC 地址在转发时会发生变化？
MAC地址仅在局域网内有效，路由器转发时需剥离原帧头部，根据路由表确定下一跳IP地址，并重新封装目标MAC地址。

（3） 路由器如何处理无法继续转发数据包？
TTL=0：丢弃数据包，返回ICMP Time Exceeded。
​​路由缺失：丢弃数据包，返回ICMP Destination Unreachable。
​​分片失败（DF标志置1）：丢弃数据包，返回ICMP Fragmentation Needed。

（4） 任务四为什么将 Size 值改为 1500 就可以产生分片？
因为以太网默认MTU为1500字节。Size为1500的ICMP报文加上IP头部（20 字节）和ICMP头部（8字节）后，总长度超MTU（1500+28=1528 > 1500），因此必须分片。

（5） 为什么任务四中的两个分片的长度分别为 1500 和 48？
第一片：数据部分 = 1480字节（MTU - IP头20 = 1480）。达到最大载荷，添加20字节的IP头。总长度 = 1480 + 20 = 1500字节，MF=1，表示后面还有分片。
第二片：剩余数据（原 1528 - 1500 = 28 字节，加上 20 字节新 IP 头，共 48 字节）。MF=0，表示最后一个分片。

实验问题回答
（1）RIP协议为什么采用UDP封装？
由于RIP需要快速广播路由更新，UDP无需建立连接，降低传输延迟。且RIP协议本身简单，仅需传递路由表项，而UDP头部开销（8字节）远小于TCP（20字节）。同时UDP支持广播和组播，便于向全网通告路由信息。

（2）在任务二中，Router3需要几个更新周期才能获得10.0.0.0的路由信息？
Router3需等待至少两个更新周期才能学习到10.0.0.0的路由。
第1周期：Router1广播初始路由表。
第2周期：Router2学习到10.0.0.0，会在下一轮更新中通告给邻居，最终Router3在第2周期结束时更新路由表。

实验拓扑


实验步骤
任务一：观察UDP无连接的工作模式
步骤1：捕获UDP传输

PC发送一个域名请求给Server，然后Server再回复一个域名应答给PC。

步骤2：分析UDP无连接的工作过程

在捕获的第一个事件中，第7层的DNS协议使用的是第4层的UDP;UDP 将 DNS协议数据封装之后，直接将数据发送出去，表明UDP是无连接的，即通信没有握手预约，也没有确认接收。

步骤3：分析UDP报文格式

UDP首部结构（总长度8字节）对应四个特征{源端口、目的端口、长度、检验和}，四个特征属性分别为16位对应2字节。UDP报文总长度（LENGTH字段） = 60字节（0x003c十六进制转十进制得到）。数据部分长度为60-8=52字节。
DNS查询字节长度为0，说明未分配；DNS响应字节长度为4；

任务二：观察TCP面向连接的工作模式
步骤1：捕获TCP事件

PC在发送HTTP请求前必须先建立一条TCP 连接，并且在 Server传输网页给PC的过程中，客户端会不时回复一个确认段给服务端，最后还要释放 TCP 连接。

步骤2：分析TCP面向连接的工作过程

第一个事件是 TCP 事件，该事件 OutLayers的Layer7中，HTTP客户端(PC)建立一个到服务器(Server)的连接，在Layer4中，PC设备尝试与192.168.1.1的端口80建立一个TCP连接。该事件第7层的HTTP使用的是第4层的TCP，PC在发送HTTP请求之前，首先尝试建立一条TCP连接，表明TCP是面向连接的。

第一个HTTP事件，TCP报文序号为1，确认号为1。

最后一个HTTP事件，TCP报文序号为1，确认号为101；
客户发送数据后，服务器的确认号会递增为客户端序列号 + 数据长度。因此数据长度=ACK-序列号，所以第一个HTTP事件中TCP报文长度为0，最后一个HTTP长度TCP报文长度为100字节，而TCP首部固定由OFFSET偏移字段决定，其中长度都为0字节。

实验总结
通过捕获和分析UDP与TCP的报文交互过程，本实验系统对比了两种传输层协议的核心特性及适用场景：
UDP具有无连接特性，可以直接发送数据，无需握手；但报文结构仅含源/目的端口、长度、校验和，比较简单且传输内容不可靠，适用于实时通信（DNS、直播）等场景。
TCP面向连接，需三次握手建立连接但能通过ACK、重传、滑动窗口保障可靠性；不过报文结构含序号、确认号、窗口大小、标志位，比较复杂，且首部长度可变，传输效率低但数据完整，适用于HTTP\FTP文件传输或邮件输送等场合。

实验问题回答
（1）TCP报文首部中的序号和确认号有什么作用？
序号：标识发送方数据流中每个字节的唯一编号，用于接收方按序重组数据。
确认号：表示接收方已成功接收的数据序号+1，用于通知发送方继续传输。

（2）无连接的UDP和面向连接的TCP各有什么优点？
UDP: 低延迟，无需握手和确认，实时性强（适合直播数据传输）；高效，报文结构简单，适合短消息传输（如DNS查询）。
TCP:通过ACK、重传、排序确保数据完整性（适合HTTP），传输可靠；同时可以实现流量控制，通过滑动窗口动态调节速率，避免网络拥塞。

4、总结体会 ARP 协议
初始状态下各PC的ARP只有有限条目，清空缓存后为空。
​​ARP请求：当PC6尝试ping另一台PC时；PC6检查自己的ARP缓存，若没有PC7的MAC地址，则发送ARP广播请求，广播帧中包含源IP(PC6)和目标IP(PC7)
所有设备收到广播后，检查目标IP是否为己有。
​​ARP响应：PC7发现请求是针对自己的，发送单播ARP响应，包含自己的MAC地址；PC6收到响应后，将PC7的IP-MAC映射存入ARP缓存。
​​后续通信：之后的通信直接使用缓存的MAC地址，不再发送ARP请求。
ARP协议实现了IP地址到MAC地址的映射，采用广播方式查找未知MAC地址的设备，缓存机制减少了网络流量，提高了通信效率。

3、总结体会交换机自学习过程
初始状态下交换机的MAC地址表清空，没有任何MAC地址与端口的映射关系，代表交换机不了解网络中各设备的物理位置（即它们连接在哪些端口上）
自学习机制在于对源MAC地址的学习，当PC8向PC9发送数据包时，交换机首先查看数据包的源MAC地址，交换机将源MAC地址（PC8的MAC）与接收到该帧的端口关联起来。在MAC地址表中创建或更新条目：PC8的MAC地址 → 端口3。
接下来对目标MAC地址进行处理，交换机检查目标MAC地址（PC9的MAC）是否已在MAC地址表中，如果存在对应条目，交换机只将数据包转发到相应端口，如果不存在（初次通信时），交换机会执行泛洪，将数据包从除接收端口外的所有其他端口转发（类似广播形式），转发到目标地址后，arp协议形成MAC地址，而后目标PC（PC9的MAC）发送回数据包给端口4，MAC地址表创建条目：PC9的MAC地址 → 端口4，端口4在交换机上把数据包交给端口3并通过端口3交还给PC8的MAC地址。随着网络流量的增加，交换机不断更新MAC地址表，每当收到新设备发送的数据包，交换机就能学习到该设备的位置信息，形成了自学习的过程。
