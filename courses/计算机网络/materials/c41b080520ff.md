## 分节 7

实验总结：
通过对比集线器与交换机在数据转发机制、冲突域和广播域管理上的差异，
本实验揭示了两者在网络架构中的核心作用与局限性：​ ​
​ ​ 集线器采用广播模式转发所有数据包（包括单播、广播和组播）。由于其物
理层工作特性，所有端口共享同一冲突域和广播域，导致潜在的冲突频发及带宽
竞争。
​ ​ 交换机基于 MAC 地址表实现单播转发，仅将数据包发送至目标主机所在端
口。每个端口构成独立冲突域，有效隔离冲突；但默认情况下所有端口仍属同一
广播域，广播流量仍会被全体接收。
​ ​ 冲突域在集线器环境下，多站点同时发送数据必然引发冲突；交换机通过端
口隔离冲突域，允许多站点并发通信。
​ ​ 而两者默认均不隔离广播域，广播包会被扩散至所有端口。​
​

实验问题回答：
（1） 集线器在接收到发送给某节点的单播包时是如何转发数据的？交换机又是
如何处理单播包的？
集线器接收到单播包后，无条件广播至所有端口（包括源端口）。
交换机通过 MAC 地址学习建立端口与 MAC 地址的映射表，单播包仅从目标
MAC 对应的端口转发。若目标未知，则泛洪至所有端口（除源端口）。
（2） 在以集线器/交换机为中心的以太网中，当多个站点同时发送数据时，是
否会发生冲突？为什么？
集线器网络在多站点同时发送数据时必然冲突。因共享介质且工作于半双工
模式，信号碰撞无法避免。
交换机网络在默认情况下，单播通信无冲突。交换机为每个端口提供专用通
道，冲突域被彻底隔离。但广播或组播仍可能导致多端口响应。
（3） 使用集线器扩大以太网规模时，有没有可能会使以太网的性能下降？为什
么？
有可能，集线器将所有端口置于同一冲突域，站点增多时冲突概率呈指数增
长（n 个站点冲突概率为 1−(1−1/n) n−1）；且总带宽固定时，多站点共享导致实
际吞吐量下降。
（4） 使用交换机扩大以太网规模时，有没有可能会使以太网的性能下降？为什
么？
一般情况下不会，交换机通过隔离冲突域和全双工模式显著提升容量。但若
存在广播风暴或者 MAC 表溢出情况可能受限，交换机可能退化为泛洪模式。

实验总结：
通过构建多子网环境，本实验深入分析了 IP 协议的核心工作机制及网络层中
路由表与静态路由配置、IP 数据包转发过程与 IP 分片机制。​ ​
路由器通过静态路由表实现跨子网通信。实验中，Router0、Router1、Router2
的路由表均配置了明确的子网路由条目，并通过默认网关指向出口设备。
​ ​ 而数据包在传输过程中，源 IP 和目的 IP 地址始终保持不变，体现 IP 协议的
逻辑寻址功能。每经过一个路由器，数据帧的源 MAC 和目的 MAC 地址会被替换
为当前路由器的出接口 MAC 和下一跳设备的 MAC 地址，体现链路层的逐跳传输
特性。且每经过一个路由器，IP 头部 TTL 字段减 1，头部校验和重新计算，确保
数据包有效性。
而当数据包大小超过链路 MTU 时，路由器会对数据包进行分片。实验中，
发送 1500 字节的 ICMP 包（含 20 字节 IP 头和 8 字节 ICMP 头）时，总长度为 1528
字节，需分片为两段：
​ ​ 第一片：1480 字节数据 + 20 字节 IP 头（总 1500 字节）。
​ ​ 第二片：48 字节数据（28 原始数据 + 20 新 IP 头）。
分片后的数据包通过相同标识符和偏移量在目的端重组。而当目标网络不存
在或路由缺失时，路由器返回 ICMP Destination Unreachable 报文。
实验问题回答：
（1） 一个 IP 分组经路由器转发后，有哪些字段会发生变化？
​ ​ TTL 每经过一个路由器减 1，防止环路。
​ ​ 头部校验和因 TTL 变化需重新计算。
​ ​ 源/目的 MAC 地址链路层重新封装，替换为下一跳设备的 MAC 地址。
​ ​ 片偏移与标志位变化当且仅当分片时需更新分片位置和末片标识。
（2） 任务二的步骤 2 中，为什么数据单元的源 MAC 地址和目的 MAC 地址
在转发时会发生变化？
MAC 地址仅在局域网内有效，路由器转发时需剥离原帧头部，根据路由表确
定下一跳 IP 地址，并重新封装目标 MAC 地址。
（3） 路由器如何处理无法继续转发数据包？
TTL=0：丢弃数据包，返回 ICMP Time Exceeded。
​ ​ 路由缺失：丢弃数据包，返回 ICMP Destination Unreachable。
​ ​ 分片失败（DF 标志置 1）：丢弃数据包，返回 ICMP Fragmentation Needed。
（4） 任务四为什么将 Size 值改为 1500 就可以产生分片？
因为以太网默认 MTU 为 1500 字节。Size 为 1500 的 ICMP 报文加上 IP 头部（20
字节）和 ICMP 头部（8 字节）后，总长度超 MTU（1500+28=1528 > 1500），因
此必须分片。
（5） 为什么任务四中的两个分片的长度分别为 1500 和 48？

由此可以看出,RIPv1 更新中不包含子网掩码,采用的是广播更新方式，广播地

实验总结
通过模拟 RIP 协议在小型网络中的动态路由过程，本实验深入剖析了距离矢
量路由协议的核心机制与 RIP 协议的基础特性：​
​ ​ 距离矢量计算：路由器周期性（默认 30 秒）向邻居广播路由表，通过跳数
衡量路径优劣，最大跳数为 15 跳（16 跳视为不可达）。
​ ​ 路由更新机制：初始启动时，路由器发送完整路由表；后续更新仅携带变化
的路由条目，减少网络流量。
​ ​ 同时我们通过调试命令（debug ip rip）可见路由器周期性发送路由更新包
（UDP 520 端口），并动态添加/更新路由表项，若某条路由长时间未收到更新
或接口断开，标记为不可达（16 跳），最终从路由表中删除。
实验问题回答
（1）RIP 协议为什么采用 UDP 封装？
由于 RIP 需要快速广播路由更新，UDP 无需建立连接，降低传输延迟。且 RIP
协议本身简单，仅需传递路由表项，而 UDP 头部开销（8 字节）远小于 TCP（20
字节）。同时 UDP 支持广播和组播，便于向全网通告路由信息。
（2）在任务二中，Router3 需要几个更新周期才能获得 10.0.0.0 的路由信息？
Router3 需等待至少两个更新周期才能学习到 10.0.0.0 的路由。
第 1 周期：Router1 广播初始路由表。
第 2 周期：Router2 学习到 10.0.0.0，会在下一轮更新中通告给邻居，最终
Router3 在第 2 周期结束时更新路由表。

## 分节 22

第一个 HTTP 事件，TCP 报文序号为 1，确认号为 1。

最后一个 HTTP 事件，TCP 报文序号为 1，确认号为 101；
客户发送数据后，服务器的确认号会递增为客户端序列号 + 数据长度。因
此数据长度=ACK-序列号，所以第一个 HTTP 事件中 TCP 报文长度为 0，最后一个
HTTP 长度 TCP 报文长度为 100 字节，而 TCP 首部固定由 OFFSET 偏移字段决定，
其中长度都为 0 字节。
实验总结
通过捕获和分析 UDP 与 TCP 的报文交互过程，本实验系统对比了两种传输层
协议的核心特性及适用场景：
UDP 具有无连接特性，可以直接发送数据，无需握手；但报文结构仅含源/
目的端口、长度、校验和，比较简单且传输内容不可靠，适用于实时通信（DNS、
直播）等场景。
TCP 面向连接，需三次握手建立连接但能通过 ACK、重传、滑动窗口保障可
靠性；不过报文结构含序号、确认号、窗口大小、标志位，比较复杂，且首部长
度可变，传输效率低但数据完整，适用于 HTTP\FTP 文件传输或邮件输送等场合。
实验问题回答
（1）TCP 报文首部中的序号和确认号有什么作用？
序号：标识发送方数据流中每个字节的唯一编号，用于接收方按序重组数据。
确认号：表示接收方已成功接收的数据序号+1，用于通知发送方继续传输。
（2）无连接的 UDP 和面向连接的 TCP 各有什么优点？
UDP: 低延迟，无需握手和确认，实时性强（适合直播数据传输）；高效，
报文结构简单，适合短消息传输（如 DNS 查询）。

4、总结体会 ARP 协议
初始状态下各 PC 的 ARP 只有有限条目，清空缓存后为空。
​ ​ ARP 请求：当 PC6 尝试 ping 另一台 PC 时；PC6 检查自己的 ARP 缓存，若没
有 PC7 的 MAC 地址，则发送 ARP 广播请求，广播帧中包含源 IP(PC6)和目标 IP(PC7)
所有设备收到广播后，检查目标 IP 是否为己有。
​ ​ ARP 响应：PC7 发现请求是针对自己的，发送单播 ARP 响应，包含自己的
MAC 地址；PC6 收到响应后，将 PC7 的 IP-MAC 映射存入 ARP 缓存。
​ ​ 后续通信：之后的通信直接使用缓存的 MAC 地址，不再发送 ARP 请求。
ARP 协议实现了 IP 地址到 MAC 地址的映射，采用广播方式查找未知 MAC 地
址的设备，缓存机制减少了网络流量，提高了通信效率。
